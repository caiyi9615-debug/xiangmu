日期：2026-10-30。继续修改同一项目，保留原数据库、DeepSeek服务端配置、图片识别、时间证据和已有计划。

## 图一的弹窗在哪里

到“我的任务”，在待核实日期旁点击 **核实时间**。列表右上角的“核实时间 · N项”可批量处理；任务更多菜单和详情也提供入口。这个界面是弹窗，不是单独的导航页面；现在已保存的任务也能随时打开，不需要重新上传。

缺年份只询问年份；剩余时长/相对时间询问完整截图拍摄基准。来自不同截图的倒计时按来源分组核实，不会拿一张图的时间计算其他截图。核实保存后，工作台、任务、日历、风险和历史同步更新。

## 界面如何变简洁

- 侧栏主要显示“今天、我的任务、识别通知、日历”。风险、变更、设置收进“更多工具”。底部保留“使用指引”。
- 我的任务从八列表格改为任务行：名称、课程、截止和独立进度。每项只有一个主要“AI安排 / 查看安排”按钮。
- 分类、优先级、材料、编辑、删除和手动调整不再平铺；通过任务名称、筛选或更多菜单打开。已提交/完成的任务不催核实时间。
- 工作台用小型统计和一份行动清单替代多块重复图表、通知和计划面板；次要内容按需展开。
- 详情、编辑页、设置和已保存计划也折叠次要信息。手机采用顺序任务行，不横向挤表格。

## AI怎样拆解并安排

1. 在任务旁点击“AI安排”，或用页面顶部“AI安排任务”创建新任务。已保存任务自动带入目标、要求和截止。
2. 描述结果和当前进展，无需先自行罗列子任务。AI补问几个针对性问题。
3. 回答后填写希望完成的日期、每天可用分钟，可选择周末不安排。工作日、集中/均匀节奏、额外休息日、单段时长和缓冲在高级选项中。
4. AI主动生成有动作、产出标准、日期与估时的子任务。先显示紧凑摘要，展开任一项可改名称、日期、分钟。
5. 点击“保存这份安排”，一次保存任务和子任务计划。**不用再次进入长篇手动DIY表单。** 需要细调时仍可进入手动排期。
6. 点击“查看安排”勾选实际完成的子任务，大任务进度随实际完成更新；100%工作量不自动等于学习通已提交。

工作量、子任务数量、任务类型均由项目与回答决定，未写死7篇报告或4个步骤。截图和测试中的报告、四个步骤只是样本。

计划目标日期不会自动写成原任务的确定截止。不能占用休息日、突破每日预算或跨过现有截止；排不下会显示原因。时长为估计，需要核对。

## 保存与取消

确认前不写入AI计划；新任务可一次保存主任务与安排。模拟存储失败时没有留下孤立主任务，原输入可重试。已存在任务保存时核对版本，其他标签页修改过则拒绝覆盖。切页或返回上一步会取消旧请求，晚到结果不能覆盖正在编辑的目标。

手动安排是用户明确选择的备用入口，选择“保存任务并手动安排”会先创建普通任务，这是按钮声明的行为。已有计划保留完成与固定记录，继续通过“查看安排”重排剩余内容；不会重新AI生成后覆盖已完成进度。

## Windows / GitHub / Render 更新

先在旧版导出JSON备份。将ZIP全部解压，把项目**里面的程序文件与子文件夹**覆盖到原目录，保留原`.env`。不要在压缩软件临时目录启动。

本地首次安装依赖运行`npm install`，然后双击`start.bat`，使用原浏览器与原地址，默认`http://127.0.0.1:8790/`。启动窗口保持打开。

GitHub上传解压后的源码，覆盖原仓库同名文件；不要只上传ZIP，也不要在仓库多套一层版本目录。本次必须包含新增`public/simple-ui.js`、`public/simple.css`及更新后的其他文件。

Render保留原有效DeepSeek密钥和变量，构建`npm install --omit=dev`，启动`npm start`，`HOST=0.0.0.0`。部署完成后Ctrl+F5，应显示V2.4.0。不要上传`.env`、私密推送配置、`node_modules`或个人备份。

同一浏览器、网址和端口保留旧数据。PWA缓存已升级为V2.4.0，包含新增页面资源。AI拆解需要有效密钥和网络，离线仍能管理已保存任务。本地提醒仍须保持网页打开；本次未代配云推送。
