# 免费系统推送试用版 · 路边队

## 先说明：上传代码不等于通知已启用

本次在现有V2.0.1上增加通知，不重建项目，保留学习通蓝色作业筛选补丁及Render端口适配。
选用现有Render Free + 你自己注册的Supabase Free（数据库＋Cron），不需要购买套餐。
Supabase免费额度、暂停规则和各网络环境会变化；不要启用付费升级，定期查看用量。

定时检查每5分钟一次，正常检查延迟0～5分钟，另加Render冷启动及推送链路延迟，没有送达时限保证。超过某阶段15分钟不再补发；已过截止时间不再推送。首次启用时已经错过的阶段不补发，未来阶段继续安排。设备离线时消息仅保留5分钟，不让旧提醒长期积压。

## 1. 先备份、更新代码

在原网页设置导出JSON备份。将本包的程序文件上传到原GitHub仓库根目录，覆盖同名程序文件，保留你已配置的Render环境变量和有效DeepSeek密钥。不要上传.env、node_modules、.env.push.generated、个人截图或备份。
本版增加web-push依赖及package-lock.json，Render仍用 npm install --omit=dev 构建、npm start启动。不要只更新ai.js，这次还有后端、前端、Service Worker和部署SQL。

本地运行需先在项目文件夹终端执行 npm install，再运行start.bat。继续使用原浏览器、原网址和原端口保留原有任务。

## 2. 创建免费Supabase项目

进入 https://supabase.com/dashboard 注册并创建Free项目，不选付费升级。记录项目URL（https://…supabase.co）。
进入项目SQL Editor，将deploy/push-schema.sql全部复制执行，创建专用提醒表及函数。
该SQL启用了RLS并禁止anon/authenticated直接访问，浏览器不使用数据库管理员密钥；所有读写经过本项目后端校验。
在项目API设置获取旧版service_role密钥（Legacy API Keys区域），只填Render环境变量，不发到聊天、不放进网页或GitHub。

## 3. 本机生成推送密钥

打开解压后的项目文件夹，在终端执行：

```
npm install
node scripts/generate-push-config.js
```

会生成隐藏配置文件.env.push.generated。用记事本打开；脚本不会覆盖已有同名文件，也不会修改原.env。
将VAPID_SUBJECT示例值改成你的真实Render HTTPS网站根地址。
这不是DeepSeek密钥，也不是邮箱授权码。请保管VAPID私钥；后续不要随意更换，否则每台设备需重新订阅。

## 4. 在Render Environment增加7项

| 名称 | 内容 |
| --- | --- |
| SUPABASE_URL | 你的项目URL，不带/rest/v1 |
| SUPABASE_SERVICE_ROLE_KEY | 你的Supabase旧版service_role密钥 |
| VAPID_PUBLIC_KEY | 刚生成文件里的公钥 |
| VAPID_PRIVATE_KEY | 刚生成文件里的私钥 |
| VAPID_SUBJECT | 你的真实https://…onrender.com网址 |
| PUSH_JOIN_CODE | 刚生成的邀请码，仅给允许使用提醒的人 |
| PUSH_CRON_SECRET | 刚生成的定时器秘密，不给普通访客 |

保留HOST=0.0.0.0和现有DeepSeek配置，让Render自动分配PORT。保存并重新部署。
网页设置显示“后台变量已配置”只代表这些变量已填写，不代表数据库、定时器和手机都已验证成功。

## 5. 设置真正独立运行的定时器

在Supabase启用Cron（pg_cron）和pg_net扩展（可在Integrations/Database Extensions中搜索）。
在Supabase Vault界面保存两个秘密：

- 名称dh_push_tick_url，值为 https://你的Render网址/api/push/tick
- 名称dh_push_cron_secret，值与Render的PUSH_CRON_SECRET完全相同

然后SQL Editor执行deploy/push-cron.sql，仅执行一次。不要把真实秘密写进上传到GitHub的SQL文件。
在Cron界面确认存在deadline-hunter-push，每5分钟执行。Cron显示成功只说明HTTP请求已入队，还要用以下SQL检查最近请求是否HTTP 200：

```
select status_code, timed_out, error_msg, created
from net._http_response order by created desc limit 10;
```

401=定时器秘密不一致；503=数据库/变量/SQL未正确配置；超时=Render唤醒或网络失败；200仅表示执行完成，需要结合返回的sent/failed检查。
请求超时设为120秒以容纳Render唤醒；依然不保证可靠到达。若扩展不可用或免费项目暂停，后台提醒不会运行，不要只靠网页按钮认为已配置成功。

## 6. 每台设备开启

所有设备访问同一个HTTPS网址，在设置找到“系统推送·免费试用”。

- 苹果：iOS/iPadOS16.4以上，Safari打开 → 分享 → 添加到主屏幕 → 从主屏幕图标打开 → 设置里开启通知。不要只停留在Safari标签页或微信内。
- 安卓：用支持Web Push的Chrome/Edge/Firefox等浏览器，允许通知；按需添加到主屏幕。部分国产浏览器及推送网络环境可能不支持。
- 电脑：支持推送的浏览器中允许网站通知，并确认系统没有屏蔽该浏览器通知。关掉标签页可以接收，但完全退出浏览器、系统省电/勿扰等仍可能影响接收。

输入PUSH_JOIN_CODE对应的邀请码（不是API密钥），点击“开启此设备通知”。这一步明确同意上传提醒摘要；不上传原始截图、通知原文或材料清单。
点击“发送测试通知”，亲自在设备通知栏确认收到。服务端“已接受”不是送达回执，也不证明Cron已运行。

## 7. 做一次真正的关闭网页测试

创建一个明确未提交的真实测试任务，截止设为北京时间当前时间后35分钟，选择日期＋时间，并勾选“我已核实时间依据”。不要用带演示标记的任务。
保存后到设置点击“同步提醒任务”，确认同步成功，再关闭网页。理论上约5分钟后到达“截止前30分钟”时点，下一个Cron检查才发送，可能进一步延迟。
同时在Supabase Cron及请求结果里检查有无执行与错误。如果没有收到，先用测试通知区分权限/网络问题和定时器问题。

## 行为与限制

- 五个阶段：24小时、12小时、3小时、1小时、30分钟，每个任务＋截止时间＋阶段有稳定ID；数据库锁定领取，避免同时扫描重复领取。网络发送成功但确认数据库失败时仍可能重试，设备用同一tag尽量合并，不能承诺绝对只送一次。
- 仅处理已人工核实完整截止时刻、明确未提交/逾期、非演示的任务。仅日期、待核实、未知状态、已提交、已完成和待批阅不提醒。
- 保存、完成、删除和改期后异步同步云端快照。同步失败不影响本地保存，但云端可能还是旧状态，设置会明确报错，请联网后重新同步。设备收到推送时还会核对本地状态，尽量拦截已完成/已删除/已改期任务。
- 目前是每台设备独立提醒，不是登录账号，也没有跨设备任务自动同步。需要多设备同一任务时先用原有备份导入，在每台设备分别订阅；一台完成不会自动修改其他设备的本地副本，需分别修改/同步。
- 免费试用最多同步200条任务；云端仅保存提醒所需的标题、任务ID、截止时刻、阶段和订阅。连续30天未同步自动清理该设备云端数据。
- “关闭并删除云端提醒”会删除此设备云端队列与订阅。清除浏览器数据之前应先执行此操作，否则设备凭证丢失，只能等待30天过期或由维护者在数据库删除。
- 不缓存首页或AI请求，Service Worker不会替换原有上传/识别逻辑。
- 部署/网络/数据库/推送厂商/系统省电都会影响时效；中国大陆某些网络访问推送厂商可能失败。这是试用，不可作为关键截止事项的唯一提醒。

## 关闭免费定时任务

Supabase Cron界面暂停或删除deadline-hunter-push；每台设备设置里关闭并删除云端提醒。无需升级或付费。
