## 改动与验证策略

在当前项目定向增加public/planner.js规则引擎、planner-ui.js界面、planner.css样式，domain任务模型保留plan/planSuggestion，AI仅提供数量快照建议，不创建已确认计划。原IndexedDB名称与版本不变。版本统一为V2.1.0，保留学习通蓝色作业规则和可选免费后台推送。

使用frontend-testing-debugging技能及项目既有Playwright/Edge路径：Browser plugin not available，不新建网站、不重做视觉。该技能要求的真实页面操作发现了拖拽后日期格收起的问题，修复为保留展开状态；并改善了预览/保存后滚动位置。测试脚本也收紧了隐藏弹窗重复按钮定位、动态复选框按稳定子任务ID定位及手机先打开侧栏再导航。

## 核心证据

- 不只测试7份报告：测试10章、5套试卷、12项范围调整及四个自定义项目阶段。
- 周末排除、指定日期排除、每日上限、自然日检查缓冲、三类节奏/自定义约束正确执行。排不下时显示剩余数量且不能保存，不自动占用休息日。
- 预览不写数据库；手动改期、固定日期、电脑拖动都做约束校验；确认前不会覆盖旧日程。
- 进度2/7=28.6%、3/10=30%、3/12=25%及100%状态独立验证；材料100%不改变任务进度，任务工作量100%也不改成已提交。
- 重排保留已完成ID、完成时间及固定日期。总量缩小不会删除已完成项；日期变化需复核，原计划保留。
- 首次51/166快照需确认；完成数不凭局部章节猜测；缺失年月或时刻时只存个人计划目标，不回填通知截止时间。
- 默认习惯继承、按周汇总、风险区分、日历安排日和截止日区分、全天计划ICS导出、刷新、备份恢复、删除计划不删主任务都验证。
- 通知更新保留已有个人计划；已完成/已提交/待批阅不因为计划落后重新催办。

## 复现

```
npm install
npm test
```

浏览器回归需要自备Playwright与Edge（或设置EDGE_PATH）。先启动测试服务，设置TEST_BASE_URL、PLAYWRIGHT_MODULE（可选本机模块路径）、TEST_EVIDENCE（保存位置），运行：

```
node tests/planner-browser.cjs
node tests/browser.cjs
```

本次实际测试地址 http://127.0.0.1:18795/ ，与用户原8790服务隔离；完成后停止测试进程。截图保存在交付outputs目录，模拟任务与测试备份未打包为用户真实数据。

## 边界

AI成功返回采用等价结构化样本/模拟响应，包含真实后端validateOutput校验，没有调用真实DeepSeek密钥或学习通账号。现有图片上传/拖拽、缺少密钥错误走真实本地接口测试。
Edge手机视口不是实体iPhone/安卓测试。不声称已替用户上传GitHub或部署Render。
计划引擎是本地规则，不是泛化自然语言理解；每日项数上限按当前大任务计算，不是跨课程工时优化。阶段按项等权，尚不按难度/工时加权。
既有免费推送仍须额外配置，并未验证真实跨设备送达。本次不改变之前的AI输出截断设置。
