# Deadline Hunter V2.1.0 个性计划版 · 路边队

## 一、这次完整做了什么

通用的大任务 → 个性化计划 → 子任务执行 → 单个大任务自己的进度条。不是固定“7篇报告”，也不是终身任务总完成率。

- 数量型：自行填写总数、单位（章节、报告、试卷、练习、阅读任务等），1～500项。
- 阶段型：自己填写阶段名称，每行一个，例如某个作品的实际制作环节。不限定任务或比赛种类。
- 习惯：可用星期、额外休息日、每天最多几项、检查/提交缓冲自然日、开始及目标日期。
- 节奏：细水长流（均匀分布）、集中推进（集中在最早可用日）、提前完成（优先用前65%的可用日，容量不足才扩大窗口）、自定义（遵守你设置的约束，再逐项DIY）。不会擅自安排到周末或排除日期。
- 预览：每周安排几项、具体哪天做哪项；可编辑名称、日期、固定日期；电脑支持拖动到日期格，手机用日期输入。预览与保存分开。
- 排不下：明确显示可安排数量和剩余数量，不生成表面上完整但违反约束的计划；必须调整后才能保存。
- 实际进度：手动勾选子任务；支持取消勾选。完成数/总数及百分比只按实际记录，不随时间增长。材料清单完成率和提交状态保持独立，100%不会自动变成已提交。
- 重排：保存前显示日期变更和移出范围的条目，保留已完成内容与固定日期。总量可以调整，但不能删掉已完成记录；缩小总量时只从末尾移除未完成项。固定日期冲突需自行调整/解锁。
- 默认习惯：可勾选保存，也可在设置里编辑，仅用于以后新计划，旧计划不会自动被改。
- 联动：工作台、任务表、任务详情显示独立进度，个人执行日程进入日历并明确“非截止日期”；风险雷达区分计划落后与通知逾期；可单独导出执行计划全天ICS。
- 备份、刷新、同网址同浏览器的其他标签页保留/同步计划数据。

这是按日期、数量及约束进行的本地规则排程，不是假装AI知道你的真实日程。每个大任务自己的每日上限不等于跨所有大任务的总时间容量；目前不自动统筹其他课程，也没有按小时拆分或自动推断阶段耗时。阶段默认等权计算，不假装等于实际工时进度。

## 二、Windows启动与旧版更新

1. 先在原网页设置导出JSON备份。
2. 下载完整ZIP，右键“全部解压”。不要在压缩包预览/临时解压目录中运行。
3. 本地已有版本：停止旧服务，将本包程序文件覆盖到原项目文件夹；保留你原来的.env，不要用空配置覆盖密钥。本包没有真实密钥。
4. 在项目文件夹（能直接看到package.json）打开终端，首次或更新依赖时执行：

```
npm install
```

5. 双击start.bat，保持窗口开启；本地默认地址 http://127.0.0.1:8790/ 。不要直接双击index.html。
6. 用原浏览器、原网址、原端口继续使用，按Ctrl+F5刷新，应看到V2.1.0。数据库仍是原IndexedDB，不另建数据库，不清空旧数据。
7. 需要AI时继续使用原有效DeepSeek配置；只用计划和本地任务管理不要求AI密钥。

## 三、GitHub与Render更新

1. 上传本包文件夹里面的程序文件及public、tests、scripts、deploy等子文件夹，覆盖原仓库同名文件。仓库根目录直接可见package.json。
2. 不上传ZIP本身代替源码；不上传.env、.env.push.generated、node_modules、个人截图/任务备份。网页手动上传不会靠.gitignore替你过滤。
3. 提交后等Render部署最新提交。构建命令仍为npm install --omit=dev，启动npm start；保持HOST=0.0.0.0，不要把PORT写死成8790。
4. 保留原Render环境变量，不需要更换有效AI密钥。部署后Ctrl+F5刷新，标题和设置显示V2.1.0。
5. 本次计划功能无需Supabase。之前的免费后台推送代码仍保留，但通知仍须独立完成云端配置；上传新包不会自动启用推送。

## 四、怎么使用

1. AI识别后先确认并保存任务，或者手动新建任务。
2. 在任务中心、工作台任务行或任务详情，点“制定个性计划”。
3. 选择数量型或阶段型，填自己的总量、单位或阶段名。
4. 设置习惯及起止日期，点“生成/重排并预览”。
5. 检查每周安排，按需改名称/日期、固定或拖动。违反休息日/每日上限/缓冲/已有截止日期时不能保存；过去的未完成日期也需重新安排。
6. 点“确认保存此计划”。只有这里才写入正式日程，不覆盖原通知截止时间。
7. 实际完成一项后勾选，查看本大任务的完成进度。未提交/已提交/待批阅等状态仍需在任务编辑中单独确认。
8. 没按计划完成，点“修改/重排剩余计划”，调整规则，预览前后差异后保存。已完成与固定日程不会被自动移动。

## 五、截图数量和进度的边界

- 明确的数量（如“交若干份报告”）或AI明确提取的workload，仅给待确认建议。
- “第1章、第2章”等序号不能当成全课程总量；缺少总量时自己填写。
- “任务点进度51/166”等完整快照可预填总数和已完成数，必须人工勾选确认后才可建立完成记录。通用子任务序号不代表识别到了对应具体章节；这些记录有“快照汇总”标记。
- 从完整截图提取进度仍依赖视觉模型，当前未连接学习通账号，不会实时抓取课程进度；局部列表不推断整门课的完成比例。
- “15号前”缺少年月时，不会猜成某年某月15号。自己填写的是计划目标日期，不等于确定的通知截止时间，不自动启用截止提醒。
- 已有任务截止变化时保留原计划并标记复核，不能自动覆盖你的已完成记录。

## 六、仍需了解

个人计划继续保存在当前网址当前浏览器。手机、电脑之间没有账号式自动同步，仍可导出/导入备份；同设备不同网址也不是同一个数据库。
删除大任务会一起删除其计划；只删除计划不会删除大任务、材料或原文。备份中包含计划和习惯，请妥善保管。
本次保留旧AI输出长度设置，之前的AI截断问题未在本升级中单独修复；不影响本地制定计划。
